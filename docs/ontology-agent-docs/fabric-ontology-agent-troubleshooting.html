Troubleshoot the ontology agent (preview) PREVIEW

This article provides troubleshooting guidance for common issues with the Microsoft Fabric ontology agent.

Authorization and access

The agent says it can't access a Lakehouse, Eventhouse, or semantic model

The agent uses your identity to read workspace data. If it can't read a source, the most common reasons are:

  • You don't have permission on that source. Confirm that your workspace role grants at least read access to the Lakehouse, Eventhouse, or semantic model. If the source is in a different workspace (via shortcut), check your role on that workspace too.
  • The source is in a different workspace and not shortcutted in. The agent only discovers items in the workspace where the ontology lives. Move or shortcut the source into the ontology's workspace.

Creating a new ontology

The agent's draft has too few or too many entity types

  • Too few: Tell the agent specifically which other entities or relationships matter for your scenario.
  • Too many: Tell the agent which entities are out of scope. Ask it to merge entities that share an identity or to fold a telemetry table into a time-series property on an existing entity rather than its own entity type.

Working with an existing ontology

The agent isn't proposing the change I asked for

  • Be specific about which entity, relationship, or binding you want changed.
  • Ask the agent to summarize its current view of the schema first. If its view is stale, ask it to refresh.
  • If you recently changed source schemas, tell the agent; it may need to rediscover.

The agent says "patch" but I asked for a full rewrite

This behavior is intentional. Patches preserve stable identifiers (IDs) and minimize the scope of changes. If you genuinely need a rewrite, say so explicitly and confirm the impact before applying. Rewriting can break downstream queries that depend on stable entity or relationship IDs.

A query returns no results

  • Confirm the table or graph actually has data in the time range you asked about.
  • If the agent ran a query that returned zero rows, it explicitly states that fact; it doesn't invent data. Ask the agent to broaden the time window, drop a filter, or inspect the schema again.
  • For GQL, the agent uses ISO GQL (not openCypher). If you're hand-checking syntax, use ISO GQL form.

Plan/Act mode

Nothing happens when I ask the agent to apply changes

You're probably in Plan mode. Plan mode is the default and it explicitly prevents the agent from making changes. Switch the chat to Act mode and ask again. The agent tells you what it's about to apply before applying.

AI/model issues

The agent stopped responding mid-turn or returned an error

The agent depends on Azure OpenAI for reasoning. Occasionally the model service has problems. The simplest recovery is to send try again as a new message in the same chat: the conversation context is preserved and the agent retries the failed turn. If the failure persists, wait a few minutes before retrying. During preview, conversation state lives only in your current browser session, so refreshing the page clears the chat and any in-progress draft. Changes you already applied (in Act mode) are part of the ontology item and remain intact.

The agent's output looks low-quality or off-topic

  • Give the agent specific feedback in the chat (what's wrong and why). Specific feedback gets you to a good result faster than generic feedback.
  • Try restating your goal with more detail.
  • If quality is consistently low, use the in-chat feedback control. The team uses that feedback to improve prompts and behaviors.
