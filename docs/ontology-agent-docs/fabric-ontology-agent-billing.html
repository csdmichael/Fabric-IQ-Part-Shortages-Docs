Ontology agent billing (preview) PREVIEW

The Microsoft Fabric ontology agent uses generative AI to build, improve, and query ontologies over your Microsoft Fabric workspace data. Because the agent calls large language models (LLMs), usage incurs costs. This article describes how billing is planned and how to control spend.

Important

The Microsoft Fabric ontology agent is currently in preview. Billing terms and pricing for general availability aren't finalized. The information in this article reflects the current direction. Microsoft announces final pricing before general availability. Check this page for updates.

How the ontology agent is billed

The ontology agent uses the same consumption-based billing model as other Copilot in Microsoft Fabric experiences, integrated with Fabric capacity. You pay only for the AI work the agent performs.

  • Capacity-backed: Agent consumption draws from the Fabric capacity that hosts the workspace where the ontology lives.
  • Operation-scoped: Charges accrue for each agent operation: creating an ontology, improving an ontology, and queries.
  • Variable by operation type: A short query consumes few tokens and incurs low cost. A full ontology draft involves many tool calls and multiple LLM passes (planning, drafting, reviewing, formatting), and consumes more tokens and therefore more cost.

For up-to-date pricing details and capacity sizing guidance for Copilot in Microsoft Fabric, see the Microsoft Fabric pricing page and Copilot in Microsoft Fabric overview.

What incurs cost

The following operations involve LLM calls and tool execution, so they incur cost:

  • Creating an ontology: clarification, discovery, drafting, validation, apply planning, and apply execution.
  • Improving an ontology: refreshing the agent's view of the current schema, patch construction, validation, apply planning, and apply execution.
  • Queries: The agent writes and executes queries in Kusto Query Language (KQL), SQL, and Graph Query Language (GQL).

The underlying Fabric services, not the ontology agent, bill for pure data storage such as the ontology definition, your Lakehouses, and your Eventhouses.

What is free during preview

During the preview, the ontology agent is provided to help customers evaluate the experience. Microsoft announces final billing turn-on dates and any preview-period concessions separately.

Tips to manage cost

  • Use Plan mode to iterate: Plan mode and Act mode both consume tokens, but iterating in Plan mode usually requires fewer total turns than iterating after applying changes.
  • Be specific: Vague prompts cause longer reasoning loops and more tool calls. Specific prompts ("add a relationship between Flight and Gate using FlightId and GateId") complete in fewer turns.
  • Trust validation: Don't ask the agent to rerun validation repeatedly without changes; validation runs automatically before each apply.
  • Reuse evidence across turns: The agent caches discovery evidence within a conversation. Asking it to rediscover the same source repeatedly is wasted work.
  • Don't keep one long conversation alive: Conversations have a 24-hour limit anyway. Long conversations carry large context, which makes each turn more expensive.

Cost visibility

When billing is in effect, ontology agent consumption appears under Microsoft Cost Management with the Fabric capacity that hosts the conversation. To see which workspaces and capacities drive spend, use Cost Management's filters and tags. This view works the same way as it does for other Fabric workloads.
